เปลี่ยนคู่มือ Word เป็นแม่แบบ 3 ฉบับบน TEF Platform

ใช้ไฟล์ร่างของสมาคมเป็นต้นแบบ แยกเป็นคู่มือ Dressage, Jumping และ Eventing ที่ใช้โครงเดียวกัน ผู้จัดการแข่งขันกรอกเฉพาะช่องที่กำหนดผ่านหน้าเว็บ ข้อความที่ไฮไลต์แดงถูกล็อกไว้ ทุกรายการจึงออกมาหน้าตาเดียวกัน แนวทางเดียวกับที่ FEI ให้ผู้จัดส่งตารางการแข่งขัน Jumping และ Eventing ผ่าน FEI Schedules Dashboard แทนการส่งไฟล์ Word

สีในไฟล์ต้นฉบับ กลายเป็นชนิดช่องในระบบ

ในไฟล์ Wordชนิดในระบบใครแก้ได้วิธีกรอกตัวอย่างจากต้นฉบับ
ไฮไลต์แดงข้อความล็อกTEF Admin เท่านั้น ออกเป็นเวอร์ชัน เช่น v2027.1ผู้จัดเห็นแต่แก้ไม่ได้กฎ กติกาที่ใช้ในการแข่งขัน, จรรยาบรรณ FEI
ไฮไลต์เหลืองช่องกรอกผู้จัดการแข่งขันแยกย่อหน้าเหลืองเป็นช่องย่อยตามชนิดข้อมูล: ข้อความ อีเมล วันที่และเวลา เลขบัญชีอีเมลจองคอก, กำหนดชำระเงิน, บัญชีธนาคาร
“ :” ที่เว้นว่างช่องรายชื่อ หรือข้อมูลหลังหัวข้อผู้จัดการแข่งขันเลือกจากทะเบียนบุคลากร TEF หรือพิมพ์ชื่อใหม่ เพิ่มหรือลดบรรทัดได้ประธานกรรมการตัดสิน, สนามแข่งขัน
xxxxxช่องตัวเลขพร้อมหน่วยผู้จัดการแข่งขันใส่ตัวเลข หน่วยถูกล็อกไว้ ระบบจัดรูปแบบให้ (คั่นหลักพัน, เลขไทย)ขนาดคอก (เมตร), ค่าคอก (บาท/วัน)
ข้อความปกติข้อความมาตรฐานของแม่แบบTEF Admin—หัวข้อ, หมายเหตุคอกม้า
ใหม่ส่วนที่เสนอเพิ่มรอ TEF ยืนยัน—บุคลากรและกฎของ Eventing, เงินประกันการประท้วง

ช่องที่กรอกจะถูกเก็บเป็นข้อมูล ไม่ใช่แค่ข้อความในไฟล์ เช่น ชื่อรายการที่กรอกครั้งเดียวจะไปปรากฏทั้งหน้าปก รายละเอียดการแข่งขัน และท้ายกระดาษ บรรทัด “ณ … วันที่ … โดย …” บนปกสร้างจากช่องสถานที่ วันที่ และผู้จัดอัตโนมัติ และผู้จัดพิมพ์แก้เองได้ถ้าต้องการข้อความอื่น

  • ไม่มีหน้าเว็บให้นักกีฬาเปิดดู

ข้อดี

  • ข้อมูลใช้ต่อในการสมัคร จองคอก ชำระเงิน

ข้อจำกัด

ข้อดี
  • มีไฟล์ Word สำหรับเก็บเอกสารหรือส่งหน่วยงานที่ขอ
ข้อจำกัด
  • ต้องดูแลแม่แบบสองที่ ควรเพิ่มทีหลังเมื่อ B นิ่งแล้ว

สิ่งที่พบในไฟล์ต้นฉบับ

ข้อความแดงในต้นแบบนี้คงไว้ตามต้นฉบับทุกตัวอักษร จุดด้านล่างควรให้ TEF Admin แก้ในแม่แบบหลัก

  • รายการกฎทั้งหมดอ้างฉบับปี 2024 ควรตรวจ edition ปัจจุบันก่อนใช้งานจริง ตรงนี้คือเหตุผลที่ข้อความล็อกต้องมีระบบเวอร์ชัน
  • เลข edition ไม่ตรงกัน: รายการกฎเขียน FEI Jumping Rules “27th edition effective 1 January 2022” แต่ท้ายจรรยาบรรณเขียน “27th edition, effective 1 January 2024”
  • คำผิดในข้อความแดง: “จำดัก” (น่าจะเป็น “กำจัด”) และหัวข้อ “c) การเกษียณม้า” ซ้ำลำดับ (น่าจะเป็น e)
  • ข้อความปกติ: “สหพันธ์ขี่ม้านานาชาติn” และ “เวลปิดคอก” ในหมายเหตุคอกม้า (แก้แล้วทั้งสองจุดในต้นแบบ)
  • รายการกฎมี FEI Endurance ซึ่งไม่อยู่ใน 3 ประเภท จึงไม่ใส่ในฉบับใดเลย
  • ย่อหน้ากติกาการแข่งขันและการประท้วงอ้างถึง “กีฬาระหว่างโรงเรียน ประจำปีการศึกษา 2567” และระเบียบกรมพลศึกษา ซึ่งเป็นข้อมูลเฉพาะรายการ จึงเสนอให้เป็นช่องกรอก
  • เอกสารใช้เลขไทยและเลขอารบิกปนกัน ระบบจัดให้เหมือนกันทั้งเล่มด้วยสวิตช์ “ตัวเลขไทย”
  • บรรทัด “ :” บางบรรทัดในต้นฉบับไม่มีหัวข้อ (เป็นบรรทัดต่อของรายชื่อ) ระบบตีความเป็น “เพิ่มรายชื่อในตำแหน่งเดียวกัน”

เรื่องที่ TEF ต้องตัดสินใจก่อนเริ่มเฟส 1

  1. ตำแหน่งบุคลากรและกฎของ Eventing ที่เสนอไว้ (Technical Delegate, ผู้ออกแบบสนามครอสคันทรี, FEI Eventing Rules) ตรงกับที่ TEF ใช้หรือไม่ และ Eventing ควรอ้าง Dressage Rules หรือ Jumping Rules ด้วยหรือไม่
  2. กำหนดส่งคู่มือฉบับร่างกี่สัปดาห์ก่อนวันแข่ง (USEF ใช้ 16 สัปดาห์ และเริ่มแจ้งเตือนที่ 20 สัปดาห์)
  3. ย่อหน้าข้อความปกติที่มีข้อมูลเฉพาะรายการ (ระเบียบที่อ้าง, เงินประกันการประท้วง) ให้เป็นช่องกรอกหรือไม่
  4. ใช้เลขไทยทั้งเล่มเป็นค่าเริ่มต้นหรือไม่
  5. ยืนยันว่าใครถือบทบาทผู้ตรวจ ผู้อนุมัติ และ TEF Admin (ร่างไว้ในแท็บ “สิทธิ์ผู้ใช้”)

บัญชีทดลอง (จำลอง) · คลิกเพื่อเข้าในบทบาทนั้น
  1. กด “เข้าสู่ระบบด้วย Google”Google ยืนยันตัวตน แล้วส่งชื่อกับอีเมลกลับมา ระบบไม่เห็นรหัสผ่าน
  2. ระบบเทียบอีเมลกับรายชื่อที่ TEF Admin เชิญไว้พบแล้วได้บทบาทและขอบเขต เช่น สโมสรหรือรายการที่ดูแล
  3. อีเมลที่ไม่อยู่ในรายชื่อเห็นได้แค่คู่มือที่เผยแพร่แล้ว และกดขอสิทธิ์ให้ Admin พิจารณา
  4. ทุกการกระทำถูกบันทึกใคร ทำอะไร กับคู่มือเล่มไหน เมื่อไหร่ เก็บตั้งแต่วันแรกที่เปิดใช้

6 บทบาท

ใครทำอะไรได้

* ทุกครั้งที่ Admin แก้แทนหรืออนุมัติแทน ต้องระบุเหตุผล และระบบบันทึกไว้ · คอลัมน์ที่ไฮไลต์คือบทบาทที่เลือกอยู่มุมขวาบน

กติกาการอนุมัติ

  • อนุมัติสองชั้น ผู้ตรวจดูความครบและความถูกต้องแล้วส่งต่อ ผู้อนุมัติตัดสินใจและสั่งเผยแพร่
  • คนที่ส่งคู่มือ อนุมัติคู่มือของตัวเองไม่ได้ ผู้ตรวจกับผู้อนุมัติของเล่มเดียวกันต้องเป็นคนละคน
  • การส่งกลับแก้ไขต้องมีคอมเมนต์อย่างน้อยหนึ่งช่อง ผู้จัดจะเห็นว่าต้องแก้ตรงไหน
  • อนุมัติแล้วฉบับนั้นถูกล็อก แก้ได้ทางเดียวคือขอแก้ไข ระบบออกฉบับใหม่แล้ววนกลับมาตรวจ

สิ่งที่ต้องขอจาก IT

  • โปรเจกต์ Google Cloud ของสมาคม พร้อมหน้า OAuth consent (ชื่อแอป โลโก้ อีเมลติดต่อ)
  • OAuth Client ID แบบ Web application และ redirect URL ของเว็บจริง
  • โดเมนของระบบ เช่น platform.tefthailand.com
  • สมาคมใช้ Google Workspace กับโดเมน tefthailand.com หรือไม่ ถ้าใช้ จำกัดบทบาทเจ้าหน้าที่ให้เฉพาะอีเมลโดเมนนี้ได้
  • รายชื่อ TEF Admin คนแรก 1–2 คน
  • นโยบาย PDPA สำหรับข้อมูลที่เก็บ ได้แก่ ชื่อ อีเมล รูปโปรไฟล์ และบันทึกการใช้งาน

  • บันทึกและประกาศผล

ข้อมูลหลักที่ระบบต้องเก็บ

Templateประเภท เวอร์ชัน วันที่มีผล รายการบล็อก
Blockชนิด (ล็อก ช่องกรอก รายชื่อ ตัวเลข ข้อความ) เนื้อหา ประเภทที่ใช้
Eventชื่อรายการ ประเภท วันที่ สถานที่ ผู้จัด สถานะในปฏิทิน
Handbookรายการ เวอร์ชัน ค่าที่กรอก สถานะ ผู้อนุมัติ วันที่อนุมัติ
Personชื่อไทยและอังกฤษ FEI ID คุณวุฒิ วันหมดอายุใบอนุญาต
Assignmentคู่มือ ตำแหน่ง บุคคล ลำดับบรรทัด
Commentคู่มือ ช่องที่อ้างถึง ผู้เขียน ข้อความ แก้แล้วหรือยัง
ChangeLogเวอร์ชัน ช่อง ค่าเดิม ค่าใหม่ เหตุผล

เทคโนโลยีที่เสนอ

  • เว็บแอปเดียว เข้าสู่ระบบด้วย Google แยกสิทธิ์ 6 บทบาท (ดูแท็บสิทธิ์ผู้ใช้) ทำได้ด้วย Supabase Auth
  • บังคับสิทธิ์ที่ฐานข้อมูลด้วย Row Level Security ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ คนที่ไม่มีสิทธิ์จึงอ่านหรือแก้ข้อมูลไม่ได้แม้เรียกตรง
  • ฐานข้อมูล Postgres เก็บแม่แบบเป็นบล็อก และเก็บค่าที่กรอกแยกจากแม่แบบ จึงเปลี่ยนแม่แบบได้โดยไม่กระทบคู่มือที่อนุมัติแล้ว
  • สร้าง PDF จากหน้า HTML เดียวกับที่เห็นในต้นแบบ ใช้ฟอนต์ Sarabun (ตระกูลเดียวกับ TH Sarabun ในไฟล์ Word)
  • ส่งออก DOCX ทีหลังในเฟส 2 ถ้ายังต้องการไฟล์ Word
